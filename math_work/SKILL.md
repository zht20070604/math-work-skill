# math_work — 数学建模论文写作规范

## 使用方式

在对话中输入 `/math_work` 即可激活本技能。激活后，AI 将严格按照以下规范执行所有论文相关操作。

## 🔄 技能自我完善规则（重要）

本技能不可能覆盖所有实际情况，也可能存在错误。**当使用本技能时发现以下任一情况**：

- 遇到了技能中**没有写到的情况**（新环境、特殊场景、技能未覆盖的细节）；
- 发现技能中的某条要求**在本机/本次任务下明显不适用或会出错**（例如技能要求的软件、命令、流程在当前环境无法正常工作）；

**AI 必须做到**（绝对禁止直接跳过或逃避）：

1. **先自己解决**：遇到技能没写到 / 解析器无法翻译的情况，主动上网查找资料、查阅可行方案（如解析器遇到不认识的 `\命令`：查该命令的标准写法 → 扩展 `LATEX_SYMBOLS` 表或新增 handler → 在 `test_omml.py` 补一条测试），并选择当前环境下能正确完成任务的方法继续执行；
2. **解决后反馈问题本身**：解决后向用户说明「遇到了什么问题 → 如何解决的 → 是否建议补充进 skill」，并给出具体、可落地的修改建议（改哪里、写什么）；
3. **征询用户同意后才修改技能文件**：用户决定采纳后，才更新 `SKILL.md`/`omml_builder.py` 等文件（改动同时回写文件头注释登记新语法 + 补测试）；
4. **不机械照搬**：当技能某条要求在本机/本次任务下明显不适用或会出错时，按技能的精神与最终目标灵活处理，并在交付时**明确告知用户实际采用了什么处理方式及原因**；
5. **无法解决也必须如实说明**：若最终无法解决，必须如实向用户说明问题所在、已尝试的途径、可用的替代方案，**绝不允许假装解决或默默放弃**。

**为什么**：技能是"死"的，实际场景是"活"的。只有每次遇到漏洞都主动反馈，技能才能越用越准、越用越全。**任何发现漏洞却不反馈、或假装解决的 AI，都是在让技能持续出错。**

本技能曾多次被 Claude 偷懒跳过关键步骤，导致论文质量严重受损。以下规则**绝对不可违反**：

| 序号 | 规则 | 违规后果 |
|------|------|---------|

| 6 | **不可跳过任何步骤**：最终工作流全部步骤必须执行，不可有遗漏 | 论文质量不可控 |
| 7 | **未验证不可声称完成**：必须用 LibreOffice 打开预览 + 截图确认，逐条检查最终检查清单 | 问题未发现，提交后丢分 |

### ⚠️ 规则 9 操作细则：图源关键参数的核对流程（2024-D Q3 翻车复盘）

当题目"文字 + 图"共同定义模型时，**建模前先执行下面的核对表**，把"哪些关键值来自文字、哪些来自图"逐项写出来，再动手设决策变量。

**核对表（建模前逐项填）**：
```
决策变量/几何量 | 题面文字怎么规定 | 图中怎么画 | 自变量的取值/个数
   间隔 sx     | （文字未提，只见于图 2 标注"间距 a"） | 图 2 沿艇长方向标注 a | 独立变量
   间隔 sy     | （文字未提，只见于图 2 标注"间距 b"） | 图 2 垂直方向标注 b | 独立变量
```
只要"图中怎么画"一列填不出/看不清/有两个不同标记 → **立即按规则 8 停下问用户**，不允许猜。

**三条禁条（犯任一条即违反规则 9）**：
1. **禁"读图注猜 + 让用户确认"当看懂**：用户一句"嗯，对"不是核对结果。图没看清就直说"我看不清图 2 里这两个间距标记，请告诉我是两个独立间距还是一个间距"，而不是自己假设成方形再设法让用户点头。
2. **禁擅自合并独立决策变量**：原题图 2 双间距 a/b（沿航向/垂直航向）是两个变量，只有存在对称性时才可令 `sx=sy`；艇命中区长 100 m、宽 20 m 明显不对称，**无对称性**。禁止写"由对称性，sx=sy=s"这类不成立的推理。
3. **禁为"方便画 2D 曲面对照/便于展示"降维**：把 (d,sx,sy) 压成 (d,s) 只为一幅漂亮寻优曲面，属于改变题意，不是建模简化。降维必须先证明题干允许，且要在正文明确写"此处将两间距合成 s"并说明理由。

**不适用规则 9 的情形**：题目只给单一值、或文字已明确规定该参数（如 Q1 的 Z=150 定值、R、σ 都是文字给出），不重复核对。

### ⚠️ 规则 10 操作细则：改码必重建、产物必须由当前源码构建（源码-产物漂移复盘）

**背景（2026-09 实测翻车）**：源码已把"同一列的三行→同一行中三列""直接归零→密度取 0""抛物线精化→有界一维搜索精化"改对了，但成品 `docx` 仍是旧句。审核第二份报告照旧报"仍错"。根因**不是改错**，而是**改了源码却漏了重新生成**：docx 停留在早于源码修改的那次构建，校验又跑在这份旧 docx 上——`verify_paper` 是**内容门**，查不出"这份 docx 是不是当前源码刚生成的"，于是全 PASS 被当成"已合格"，把旧稿交了出去。

**事实源约定（强制）**：
- 论文的每一个字、每一张图、每一个数字，**只允许来自生成代码**（`build_paper_*.py` + `make_figs.py` + `solve.py`/`paper_results.py`）。`docx/pdf` 只是由它们构建出来的**产物**，**不是事实源**。
- **禁止**用 python-docx 直接改 docx 里的文字/数字/图；**禁止**手动挪动产物位置。要改 → 回源码改 → 重建。

**改码必重建（强制）**：只要改了下列任一个文件，就必须把整链重跑一遍，并把校验、回归核对跑在**这次刚生成**的产物上：
  ① 重跑求解脚本（更新数据/*.pkl）→ ② `make_figs.py`（重画全部图）→ ③ `build_paper_*.py`（重建 docx）→ ④ LibreOffice 转 PDF。
  顺序不能省、不能只跑到一半；`verify_paper` / `check_numbers` / LibreOffice 预览**只对这一步刚产生的 docx/pdf 做**。
  校验前**默认当作"当前 docx 是旧的"**——先重建再校验，彻底杜绝拿旧稿核对。

**审计/用户反馈回归核对（强制，最容易被漏）**：收到外审/用户的具体意见后，先列一张**回归表**，重建后在新产物里逐条核对"确实变了"：

  | 反馈所述 | 旧表述（原文摘录） | 应改成 | 重建后新 docx 检索 |
  |---|---|---|---|
  | 第10页行列混淆 | 同一列的三行命中带纵向中心相同 | 同一行中三列…由三列中最大的有效伸出决定 | 旧句 **0 命中** / 新句已出现 |
  | 第5图 120m 归零 | 密度在 120 m 处直接归零 | 深度小于 120 m 处密度取 0，120 m 右侧由正值开始 | 旧句 **0 命中** / 新句已出现 |
  | 5.3.2 精化措辞 | 一维抛物线精化至收敛 | 有界一维搜索精化至收敛 | 旧句 **0 命中** / 新句已出现 |

  每条规则：**旧表述必须在重建后的 docx 里 0 命中，正确表述必须已出现**；否则说明重建没生效或改错了地方，继续改，**不算完成**。全部核对完，再跑 `verify_paper` / `check_numbers`（两者都只对这份新产物）。

## 一、论文整体结构（固定顺序）

```
首页（独占一页）：
  标题 + 摘要 + 关键词

正文（第二页起）：
  1 问题重述
  2 问题分析
    （可按需分为 2.1/2.2/2.3 或不分子节）
  3 模型假设
  4 符号说明
  5 模型的建立与求解
    5.1 问题一模型的建立与求解
      5.1.1 模型的建立
      5.1.2 模型的求解
    5.2 问题二模型的建立与求解
    5.3 问题三模型的建立与求解
    （5.x 按实际题量 N 展开为 5.1~5.N，每问一节；如赛题 4 个小问则写到 5.4）
  6 模型的分析与检验
  7 模型的评价、改进与推广
    7.1 模型的优点
    7.2 模型的缺点
    7.3 模型的改进
    7.4 模型的推广
  8 参考文献

附录（另起一页）：
  附录                          ← 一级标题"附录"必须真实存在（黑体14pt居中），不能只有下面的二级标题
    附录1 支撑材料清单
    附录2 数据样例（可选）
    附录3 程序源代码
```

### 约束

- 论文的问题数量以赛题为准（CUMCM 通常 3~4 个小问，以实际题量为准），必须完整覆盖全部子问题，不得遗漏、不得自设数量
- 每个问题的回答必须详细、完整，不能过于简要（详细度量化底线见第二节 5"文字详细度"：正文页均 ≥2000 字、解读短语数 ≥ 图/表提及数）
- 无封面页、无目录
- 正文不展示代码/算法（源代码放在附录中即可）
- **首页必须独占**：标题+摘要+关键词必须放在第一页且仅在第一页。关键词段落结束后，**必须立即插入分页符**（`add_page_break(doc)`），"1 问题重述"从第二页开始。**禁止**在第二页或之后再次出现摘要或关键词内容
- **附录前必须分页**：参考文献之后必须立即插入分页符，附录从新的一页开始

## 二、各部分内容要求

### 首页（独占一页，不可跨页）

| 元素       | 要求                                                                                 |
| ---------- | ------------------------------------------------------------------------------------ |
| **标题**   | 优先使用"基于主要模型/方法"的命名方式（推荐），也可直接使用赛题题目                  |
| **摘要**   | 全篇最重要的部分。评阅老师时间有限主要看摘要。应在其他部分完成后最后写，反复打磨修改 |
| **关键词** | 4~6 个，可选主要模型名称或体现论文核心内容的词                                       |

**页面规则（强制）**：
- 标题、摘要、关键词**必须全部放在第一页**，不允许跨页
- 关键词段落后**必须立即插入分页符**（`add_page_break(doc)`），确保正文从第二页开始
- **禁止**在第二页或之后任何位置再次出现标题、摘要、关键词内容
- 生成代码中，首页内容和正文之间必须有一个 `add_page_break(doc)` 调用

**⚠️ 封面高度陷阱（满页溢出）——2025-E 实测踩坑，必须量化验证**：

即使分页符、字号、行距、缩进全部符合规范，**摘要写得过长**时，标题+摘要+关键词在 LibreOffice 渲染下会**恰好超出 1 页高度**，关键词段被整段挤到第 2 页独占；而同一 docx 在 Word/WPS 里可能刚好放得下。**症状 = "Word 里首页正常，转 PDF 后关键词单独占第 2 页"**。这不是分页符缺失，根因是：

- 封面内容"顶格到边"——内容带底端已贴到下边距附近（余量 <10px@150dpi），任何度量差异都会触发翻页；
- 分页由排版引擎按**字体度量**计算：Word 用真实 SimSun，单倍行距下 CJK 行高较紧凑，恰好放下；LibreOffice 无 SimSun 时做字体替换（如换 Noto CJK），行高略大，把最后 1~2 行（即关键词）挤出页外。

**判定标准（必须量化，禁止目测）**：渲染后**剔除页脚带**，内容带底端距下边距线（150dpi 下 `y = 页面高 − 150`，A4 为 1604px）的余量 **必须 ≥40px（≈7mm）**。余量 <10px 即"满页临界"，必然有外溢风险。

**修复（唯一正确解）**：**精简摘要文字**。摘要的"结构"（开头段 + 每问一段 + 结尾段）与"格式"（12pt、行距 1.0、首行缩进 36pt）是强制的，但**"长度"不强制**——把 6 段压缩到共 **700~800 字**（删冗余修饰语，**保留全部数值与结论**：识别时刻、滞空时间、起跳角、R²、相关系数、配对检验 t/p、预测因子、预测值/区间、各训练周期成绩等），封面即可在两种渲染器下都放得下。**严禁**用改行距/缩进/字号来偷空间（违反格式规范，且治标不治本）。

**验证（修改后必须跑）**：重新转 PDF 后——① `pdftotext -f 1 -l 1` 末行应为关键词；② `pdftotext -f 2 -l 2` 首行应为正文（"1 问题重述"），无"关键词独占第 2 页"；③ 测量 p1 内容带底端余量 ≥40px。验证脚本可直接照抄：

```python
"""封面高度验证：p1 内容带底端距下边距余量必须 ≥40px@150dpi（≥40px 即 PASS）"""
import subprocess, os
from PIL import Image
import numpy as np
WORK = r'<论文目录>'                      # 改为实际目录
PDF = os.path.join(WORK, '论文.pdf')
subprocess.run([r'<pdftoppm绝对路径>', '-r', '150', '-f', '1', '-l', '1',
                PDF, os.path.join(WORK, '_p1')], check=True)   # 输出 _p1-1.ppm
img = np.array(Image.open(os.path.join(WORK, '_p1-1.ppm')).convert('L'))
h, w = img.shape                            # A4@150dpi = 1754px
rows = (img < 210).sum(axis=1)              # 非白像素按行计数
bands, inb = [], False
for y, c in enumerate(rows):
    if c > 3 and not inb: start, inb = y, True
    elif c <= 3 and inb: bands.append((start, y - 1)); inb = False
if inb: bands.append((start, h - 1))
body = [b for b in bands if b[1] < h * 0.93]  # 剔除页脚（页码）带
margin = (h - 150) - body[-1][1]              # 下边距线 y = 1754-150 = 1604
print(f'内容带{len(body)}条 底端={body[-1][1]}px 下边距余量={margin}px →',
      'PASS' if margin >= 40 else 'FAIL：满页临界，必须精简摘要后再测')
```

### 1 问题重述

- 用自己的语言重新描述问题，**绝对不可照抄原题**（会查重）
- 语言简明扼要，不必面面俱到
- 目的：吸引读者继续阅读

### 2 问题分析

- 每个问题单独分析，可根据实际情况决定是否需要分子节（2.1/2.2/2.3）、是否需要流程图
- 内容结构：题目中的信息/条件 → 整体分析 → 确定方法 → 建模思路
- 分析过程简明扼要，**不需要放结论**

### 3 模型假设

- 题目明确给出的假设条件
- 排除小概率事件（黑天鹅等）
- 仅考虑核心因素，忽略次要因素
- 所用模型要求的假设
- 对模型中参数形式/分布的假设

### 4 符号说明

- 用一张表格列出重要变量
- 临时变量可不放
- 下文首次出现时仍需解释

### 5 模型的建立与求解

- 每个问题独立一节
- 模型建立：将问题抽象为数学表达式，基于问题分析和模型假设
- 模型求解：借助软件（Matlab, SPSS, Lingo, Excel, Stata, Python 等）
- 可对已有模型改进或优化（创新点和亮点）
- 可用不同模型解决同一问题
- 智能优化算法/数值计算方法需简述计算步骤
- 求解结果过长时放入附录

**文字详细度（强制）**：每个子问题的"模型求解"必须有完整叙述链 **问题→方法→图表→解读→结论**。图表只是叙述的支撑，**禁止只放图表不加解读**。判据分"内容要素门（FAIL）"与"密度诊断（不 FAIL）"两级：

- **内容要素门（强制，缺一即 FAIL）**：每个解读段必须同时含 ①**具体数值变化**（如"到达时刻由 12.17 min 增至 18.10 min"，禁止"时刻发生变化"这类无信息表述）、②**阶段/趋势规律**（先快后慢、近端早远端晚、随参数单调等）、③**原因或物理/模型机理**（对应到假设/公式，如"末端流量趋零"）。只复述图注、只说结论不说原因的一律 FAIL。
- **注水黑名单（禁止）**：空洞总结（"综上所述，模型表现良好"）、同义反复/复述图注、无信息量结尾（"这对应急救援有一定意义"）、形容词堆砌（"显著提高/大幅改善"而无数值支撑）。
- **专业语体清单**：结论带限定条件（"在 0.2~0.5 m 阈值范围内…"）；因果链写到机理/假设层；术语统一、禁口语（"谁先到听谁"→"取较早到达者"；"水流走得更快"→"推进速度 v=q/A 更大"）；解读 ≠ 图注复述。
> 文风整体判定（专业/不空泛/不口语三分法）、六类 AI 味模板对照与机检阈值见**第十节**。

**物理/术语自洽（强制——2024-D 审计踩坑，写前查）**：正文解释公式与模型时，逐句对照"这句话在物理上/参数定义上是否成立"。三类高频错误（都是"公式和程序对、文字解释错"）：

| 错误 | 症状 | 正确 |
|---|---|---|
| **参数定义混乱** | 把截断前分布的定位参数当截尾后的均值/方差（如 2024-D 把 `h0=150, σz=40` 叫"截尾正态的均值、标准差"） | 截尾分布 `f_Z(z)=φ((z−h0)/σz)/(σz[1−Φ((l−h0)/σz)]), z≥l` 里的 `h0, σz` 是**被截断前**正态分布的位置/尺度参数；截尾后的实际均值 `E[Z]`、标准差 `SD(Z)` 需另行用截尾矩公式算（本例 `E[Z]≈165.575 m, SD≈29.835 m`）。符号表措辞写"未截断分布的位置参数/深度定位值"，不得写"截尾分布的均值/标准差" |
| **解释与公式矛盾** | "更深处由触发引信保留足迹命中"——与 `P_2(d)=∫_l^{d+R+c} f_Z M(ρ)dz` 矛盾（2024-D Q2） | **`Z>d+R+c` 时命中区为空、P=0**（潜艇比爆深更深；深弹已由定深引信在艇外引爆、目标超出半径）。触发引信"下穿艇体上表面"保留足迹命中，对应的是**潜艇较浅**（Z 小）的情形，不是"更深处"。先理清物理方向再写 |
| **断言过强/近似夸大** | "全程不引入近似"——但实际用了 PCHIP 插值、梯形/Euler 求积、等距网格、粗网格+局部搜索，都是数值近似 | 改为"几何切片关系是精确的；概率积分采用经步长收敛性检验的数值近似"。**涉近似的断言要在正文给收敛性证据**（两套步长对比、与蒙特卡洛交叉的残差），并如实写明近似来源 |

> **检查方法**：写完物理解释段后，把"公式里每个变量取极端值（如 Z 最大/最小、d 极端）代入，看文字描述是否仍成立"。成立则通过；发现"文字话术"与公式/代码行为不一致时，以公式与代码为准改文字，禁止反过来为迁就话术改模型。
> **蒙特卡洛验收口径（强制）**：凡用蒙特卡洛做交叉验证/检验，必须一并给出**抽样量 + 标准误 + 95% 误差半宽**（或置信区间），结论写"解析/数值积分与蒙特卡洛结果在抽样误差范围内一致"；**禁止**把两者的点差 0.008pp 当成"积分误差上界"或声称"验证到小数点后四位"。按样本量 `n` 估算 `se≈√(p̂(1−p̂)/n)`。
- **密度诊断（不 FAIL，仅提示）**：正文页（排除首页、参考文献、附录页）平均字符数可参考约 2000~3000 字/页（获奖论文实测约 3000）。低于 1800 提示"可能过简，检查是否有图无解读"，**但以内容要素门为准，不单凭字数 FAIL**。统计脚本：
  ```python
  # 正文页均文字量：pdftoppm -r 72 渲染后逐页 OCR 统计字符数，取正文页平均
  # （排除首页=封面+摘要、参考文献页、附录页）
  import subprocess, os, glob
  from PIL import Image
  WORK = r'<论文目录>'; PDF = os.path.join(WORK, '论文.pdf')
  subprocess.run([r'<pdftoppm绝对路径>', '-r', '72', PDF, os.path.join(WORK, '_pg')], check=True)
  # 对每页调用 Windows OCR（见会话内 _ocr.ps1），统计字符数，正文页平均仅作密度参考
  ```
- **解读短语数 ≥ 图/表提及数**：全文 `观察图X可知` / `由图X可知` / `分析表X可知` / `由表X可知` 等解读短语总数必须 ≥ 图/表提及总数（获奖论文 44 次解读 vs 37 次提及，即每个图表后都有解读；若 20 次提及只有 4 次解读 = 不合格）。
- **解读段禁止一句话带过**：至少包含内容要素门三要素（具体数值 + 阶段/趋势 + 原因/机理；模板与实例见第三节"图文排布"）。

**跨体型/跨镜头预测禁止像素量纲外推（强制）**：预测对象与训练集体型（身高/体重/年龄）或拍摄条件（镜头远近/分辨率）差异较大时，**禁止直接使用像素量纲特征做跨群体外推**（如用成人回归的"水平速度 px/s、重心高度 px"预测 6 岁儿童成绩，会产生系统性偏差）。应优先使用**无量纲特征**（角度、比例、标度比如"距/高比"）或**做体型归一化**，并在正文说明理由。

**结果数字单一数据源（强制）**：正文/表格中的**所有结果数字**（到达时刻、覆盖数、灵敏度值、距离/时间/天数等）必须从"结果文件 + 门面"取数，**禁止在生成脚本里写死结果字面量**。做法：
- 求解脚本把全部结果写入结果文件（如 `D_results.pkl`）；新建"门面"模块统一暴露命名访问器（如 `q2_arrival(net, i)`、`n_pts(net)`、`sens_val(net, kind, key)`），缺失数据时给出可执行提示（"重跑求解脚本"）。
- 生成脚本顶部调用门面 `check()` 早失败；正文数字一律 `FI('%.2f min' % R.q2_arrival(...))` 式格式化，**禁止 `'15.88'` 这类字面量**（表内数据同此）。
- 参数或模型变更后**先重跑求解脚本再生成正文**，数字自动同步，杜绝"模型已改、正文还写旧数"。
- 用数字校验脚本 `check_numbers.py` 自动校验（Step B 漂移扫描：结果值被写成字面量 → 退出码 1），**禁止人肉筛查**；该脚本**每论文从 `tools/check_numbers_template.py` 复制**并改写 `derived()` 枚举本题结果集合，详见本小节下方「数字校验脚本」模板块。

**反杜撰（强制）**：结果数字**查不到时先查证（结果文件/原始数据），查不到就向用户反馈**，禁止编造或手填。`check_numbers.py`（从模板复制版）Step C 会拦截"带结果单位却不在白名单"的数字（退出码 2）——例如把 P0000 的"约 8.3 天"错写成"约 50 min"、把端点高程范围错写成"1.31~40.37 m"；被拦截后必须核实来源，不得绕过或改白名单放行。

**数字校验脚本 check_numbers.py（强制，每论文新建）**：
- 每篇论文把 `tools/check_numbers_template.py` **复制**到论文程序目录并改名 `check_numbers.py`（与 `build_paper_X.py`、结果门面同目录）。模板内含完整扫描逻辑（Step B 漂移 → 退出码 1、Step C 反杜撰 → 退出码 2）与写法示例，**只改写 `derived()`**：把"正文会出现的所有结果数字"用门面访问器逐项 `_add(value, spec, tag)` 取入；`spec` = 正文显示格式（如 `'%.2f'`），易与图/表号冲突的小整数必须给 `tag`（如 `r"\s*min"`，按"值+单位"精确匹配）。其余照抄不动。
- **禁止从旧任务目录复制旧版 `check_numbers.py`**：旧版枚举的是旧题结果集合，会漏检本题；一律按本模板用本篇门面重建（模板头部亦注明）。
- 运行：`python check_numbers.py [build_paper_X.py]`——先重跑求解脚本、再跑它（防"旧结果校验新脚本"）；退出码 0 才可进入最终检查（见检查清单 20d/20e 与第八节工作流）。

**可复现性（强制——外部审计可复现性扣分项，生成前查）**：论文附带的代码与元数据必须能让"另一台机器按论文附件完整重建 Word"。

1. **禁止硬编码机器绝对路径**：生成脚本、求解脚本里不得出现作者机器专属路径（如 `C:\Users\<某人>\...`）。脚本内目录一律相对位置（`os.path.dirname(os.path.abspath(__file__))`）或运行时传参。**凡脚本含 `C:\Users\`、`D:\tool\` 这类本机路径即为违规**，改掉再交。
2. **依赖必须随产物捆绑**：生成脚本 `import omml_builder` 时，`omml_builder.py` 必须**放在论文程序目录随附件一起提供**（复制一份，不做越层 import）；禁止只写 `sys.path.insert(0, r'技能tools路径')` 指向技能仓库——那样换机跑就 `ModuleNotFoundError`。正确写法：把 `omml_builder.py` 复制到论文目录，`sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))` 后本地导入。
3. **meta/结果元数据必须与实际一致**：结果文件里的元数据（`rng_seed`、参数表、版本）必须等于实际运行时用到的真实值。蒙特卡洛实际用种子 5/17/19 就写 5/17/19，**禁止**随便填个 `rng_seed=1234` 占位。元数据项建议含：求解脚本哈希、结果生成时间、软件版本、参数配置哈希。
4. **结果校验脚本不能只检查键**：`check()` 若只断言"结果字典含某几个键"是假校验（旧结果配新程序照样过）。至少比对参数配置哈希 + 结果时间戳。

**分页符写法（避免空白页）**：推荐把分页符**追加到上一段末尾**，而不是用独立的 `doc.add_page_break()` 段落——当上一页恰好写满时，独立空段落会被挤到下一页顶部，产生一张空白页（实战中已实测出现）。正确写法：

```python
from docx.enum.text import WD_BREAK
# last_p = 关键词段 / 最后一条参考文献段（分页前的内容段）
last_p.add_run().add_break(WD_BREAK.PAGE)
```

`doc.add_page_break()` 写法仍可用，但要意识到满页时可能产生空白页；关键词后、附录前**必须**分页（无论用哪种写法）。

**分页空白页根因#2（2024-E 实测，必须遵守）**：**禁止对表格单元格段落设 `keep_with_next=True`**。若写成 `for row in table.rows: for cell in row.cells: for para in cell.paragraphs: para.paragraph_format.keep_with_next = True`，整张表会与后续所有表/图注/正文**全部链式绑定**，Word 把这整块强行推到下一页，剩余空间被撑成一大片空白页（E 题实测：第 5/6/7/20 页大面积空白，删掉该循环后恢复）。表格跨页应靠 `tblHeader` 重复表头 + 每行 `cantSplit` 控制，而不靠单元格 keepNext。

**可视化丰富度（强鼓励）**：不要只画朴素的二维折线/柱状图，优先使用**三维图、热力图、多子图组合**等高信息量可视化，提升论文表现力：

- **三维图优先**：当数据具有空间结构（物体/人体运动轨迹、网络拓扑、地形/巷道/三维落差、参数空间）或需要展示三维深度/多维关系时，**必须使用三维图**（matplotlib `Axes3D`）。同一对象可先画二维平面布局图、再画三维立体图**对照呈现**（如获奖作品先画平面示意图再画三维立体示意图）。
- **高信息量图型**：相关性/相似度矩阵用**热力图**（`imshow` + colorbar + 数值标注）；多维指标对比用**多子图组合**（2×2 或 1×N `subplot`）；按需还可使用曲面图、等高线、矢量场/流线、雷达图、箱线图等。
- **数量引导**：每个子问题至少配 **1~2 张图**（结果图 + 方法/数据示意图），信息丰富优先，不设硬性上限。

**三维图铁律**（与二维完全一致）：中文字体 SimHei/黑体（含 z 轴、刻度、colorbar 文字）、图内文字≥10pt、**禁止 `plt.title()`/`fig.suptitle()`**、图注在图下方居中。

from matplotlib.patches import FancyBboxPatch

def _mm_box(ax, x, y, w, h, text, fc, fs=10, bold=True, ec='0.25', ls=1.35):
    ax.add_patch(FancyBboxPatch((x, y), w, h, boxstyle="round,pad=0.35",
                                fc=fc, ec=ec, lw=1.2))
    ax.text(x + w / 2, y + h / 2, text, ha='center', va='center',
            fontsize=fs, fontweight='bold' if bold else 'normal', linespacing=ls)

def fig_mindmap():
    """图X 模型整体思维导图（自上而下分层树：根节点→各问题→方法要点）"""
    fig = plt.figure(figsize=(9.5, 5.8))
    ax = fig.add_axes([0, 0, 1, 1]); ax.axis('off')
    ax.set_xlim(0, 100); ax.set_ylim(0, 60)
    # ① 根节点：全文模型名两行，每行≤13字
    _mm_box(ax, 32, 52, 36, 7, '论文模型名称\n（第2行）', '#ffd54f', fs=14, ec='#c49a12')
    # ② 主干 + 水平总线（根底 → 全部问题框）
    qx = [13.5, 36.5, 63.5, 86.5]
    ax.plot([50, 50], [52, 50], color='0.35', lw=1.2)
    ax.plot([qx[0], qx[-1]], [50, 50], color='0.35', lw=1.2)
    for qxi in qx:
        ax.annotate('', xy=(qxi, 48), xytext=(qxi, 50),
                    arrowprops=dict(arrowstyle='-|>', color='0.35', lw=1.2))
    # ③ 问题框（一级分支，一行4个，整行≤10字）
    qq = [(3, '问题一 短标题', '#b3d9ff'),
          (26, '问题二 短标题', '#c8f0c8'),
          (53, '问题三 短标题', '#ffd9d9'),
          (76, '问题四 短标题', '#e6d9ff')]
    for i, (x0, qt, col) in enumerate(qq):
        _mm_box(ax, x0, 40, 21, 8, qt, col, fs=12, ec='0.45')
        ax.annotate('', xy=(qx[i], 26), xytext=(qx[i], 40),
                    arrowprops=dict(arrowstyle='-|>', color='0.35', lw=1.2))
    # ④ 方法要点框（二级分支，白底+彩色边框，3行每行≤10汉字）
    mm = [(1, '要点1\n要点2\n要点3', '#2f7bd6'),
          (25.5, '要点1\n要点2\n要点3', '#2ca02c'),
          (51, '要点1\n要点2\n要点3', '#d62728'),
          (75.5, '要点1\n要点2\n要点3', '#7f5fd6')]
    for i, (x0, mt, col) in enumerate(mm):

**文字填充规则**：
- 根节点 = 全文模型名（2 行，每行 ≤13 字）。
- 问题框 = "问题N 短标题"（整行 ≤10 字），四色按 蓝/绿/红/紫 顺序。
- 方法要点框 = 3 行，每行一个方法/结果要点（如"单因素相关分析""岭回归 R^2=0.89""纠正前后配对检验"），每行 ≤10 个汉字；写不下就精简措辞，**禁止靠缩小字号硬塞**。
- 方法要点里放真实结果数据（如 `预测成绩≈1.04 m`、`R^2=0.89`、`k=0.374`），让导图信息量足、不空洞。
- 特殊符号用 SimHei 已覆盖的写法：`R^2`、`Δ`、`≈`、`·`、`/`。**禁止 `²` `³` 等 SimHei 缺失的上下标字符**（会渲染成豆腐块），所以平方一律写 `R^2`/`m^3` 而非 `R²`/`m³`。

**画完后必须自动验证文字不出框**（照抄；`qq`/`mm` 为上节同名列表，`bs` 顺序 = 根 + 4 问 + 4 方法）：

```python
fig.canvas.draw(); rr = fig.canvas.get_renderer()
inv = ax.transData.inverted()
box_specs = [(32, 52, 36, 7)] + [(x0, 40, 21, 8) for x0, _, _ in qq] \
          + [(x0, 10, 24, 16) for x0, _, _ in mm]
for txt, bs in zip(ax.texts, box_specs):
    ex = txt.get_window_extent(renderer=rr)
    (x0, y0), (x1, y1) = inv.transform([(ex.x0, ex.y0), (ex.x1, ex.y1)])
    bx0, by0, bw, bh = bs
    if not (x0 >= bx0 and x1 <= bx0 + bw and y0 >= by0 and y1 <= by0 + bh):
        print('⚠ 文字超出框：', txt.get_text())
```

有任何一行提示超框，就**缩短/拆分该行文字后重画**，全部通过才算完成。

**若赛题不是 4 问**：问题框数量随题量变——N 问就把 `qq`/`mm`/`qx` 换成 N 个等宽框，问题框中心等距 23、首框中心 13.5（`qx=[13.5+23*i for i in range(N)]`），水平总线两端 = 第 1 与第 N 个问题框中心；其余参数不变。

**其他排列方式仅当分层树明显不适用时允许**（如只有 2 问、或数据天然适合环形/左右分列），但字号底线（根≥14/问题≥12/要点≥11.5pt）、文字不出框、图幅满页宽、OCR 可读四项标准**不得低于**分层树。

**示意图（必须）**：每个子问题的模型建立/求解处，至少配 **1~2 张示意图**，直观展示数据、方法与结果。类型参照获奖作品：**数据/对象示意图**（人体关键点标注图、巷道/网络平面图、场地对象示意）、**方法示意图**（检测/微分过程、算法流程、阈值判据示意）、**结果示意图**（拟合曲线、轨迹、检测时刻标注图）。全部用 matplotlib 绘制，遵守上述全部图片铁律。

**标注类示意图防重叠（强制——人体关键点/网络节点等带对称结构的标注图）**：

对称关节/节点（左右肩、髋、膝、踝、脚跟等）在图上相距仅几个像素，若所有标签共用同一固定偏移（如 `xytext=(7,5)`），标签必然互相重叠导致看不清（2025-E 图2 实测踩坑）。**必须用左右分列 + 引导线 + 贪心下推防碰撞**，并在保存后**程序化验证两两不重叠**。

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| 左右列锚点 | 左列 `x=305`、右列 `x=640` | 身体左半身点标右列、右半身点标左列，标签展开到骨架外侧 |
| 对齐方式 | 左列 `ha='right'`、右列 `ha='left'` | 向远离骨架方向展开 |
| 引导线 | `color='0.55', lw=0.8, ls='--'` | 从关键点画虚线到标签，`zorder=2` |
| 同列最小中心距 | `GAP=30`（数据单位） | 按 y 排序后贪心下推保证间距 |
| 顶部特殊标签 | `y = top - 30`（头顶上方） | 如"鼻"，`ha='center'` 居中 |
| 字号/画布 | `fontsize=11`、`figsize=(6.6, 7.6)` | 对应论文中 11cm 放置宽度 |
| 数据范围 | `xlim(260, 675)`、`ylim(585, 158)`（倒置） | 按实际关键点范围缩放，`set_aspect('equal')` |

模板（直接照抄；`kp` 为 `(N,2)` 坐标、`ax` 已建好、`labels` 为 `{idx: ('名称', 列)}`，列 `'L'/'R'`，`None` 表示顶部特殊标签）：

```python
GAP, COL_L, COL_R = 30, 305, 640
labels = {0: ('鼻', None), 11: ('左肩', 'R'), 12: ('右肩', 'L'),
          23: ('左髋', 'R'), 24: ('右髋', 'L'),
          25: ('左膝', 'R'), 26: ('右膝', 'L'),
          27: ('左踝', 'R'), 28: ('右踝', 'L'),
          29: ('左脚跟', 'R'), 30: ('右脚跟', 'L')}
ok = kp[(kp[:, 0] != 0) | (kp[:, 1] != 0)]
top = np.nanmin(ok[:, 1])                 # 身体最上端（图像向下，y 小=上）
groups = {'L': [], 'R': []}
for i, (lab, col) in labels.items():
    if col is None or (kp[i] == 0).all():
        continue
    groups[col].append([kp[i, 1], i, lab])
for col, colx in (('L', COL_L), ('R', COL_R)):
    lst = sorted(groups[col])             # 按 y 排序
    for k in range(1, len(lst)):          # 贪心下推：中心距不足则下移
        if lst[k][0] - lst[k - 1][0] < GAP:
            lst[k][0] = lst[k - 1][0] + GAP
    for y, i, lab in lst:
        ha = 'right' if col == 'L' else 'left'
        ax.plot([kp[i, 0], colx], [kp[i, 1], y], color='0.55', lw=0.8, ls='--', zorder=2)
        ax.text(colx, y, lab, ha=ha, va='center', fontsize=11, zorder=4)
if not (kp[0] == 0).all():                # 顶部特殊标签（如鼻）：头顶上方
    ny = top - 30
    ax.plot([kp[0, 0], kp[0, 0]], [kp[0, 1], ny], color='0.55', lw=0.8, ls='--', zorder=2)
    ax.text(kp[0, 0], ny, '鼻', ha='center', va='center', fontsize=11, zorder=4)
ax.set_xlim(260, 675); ax.set_ylim(585, 158)
ax.set_aspect('equal')
```

**图文排布（强制——从获奖论文反推，2025-E 复现时踩坑）**：

获奖论文（参考素材：`数学建模素材/e/*.jpg`）的核心排版模式：**每个图/表都嵌在叙述流里——前置引导句引入、图后紧跟解读段**。反例：2025-E 重写版把图2~6、图7~10、图11~14 各连排成三大图组、组末尾才统一讲解，观感明显差于获奖作品。规则如下：

1. **禁止图/表连排**：正文中任何相邻两张图（或图与表）之间必须隔有 **≥1 个正文段**；禁止"图1、图2、图3…连续插入、末尾统一讲解"。自动判据（生成 docx 后必须跑，有 FAIL 必须拆开并补解读段）：

   ```python
   # 图注连排检查：相邻两个"图X"图注段之间必须≥1个正文段，输出必须全为0
   import re
   from docx import Document
   from docx.oxml.ns import qn
   doc = Document(r'<论文docx路径>')
   seq, paras = [], list(doc.paragraphs)
   for p in paras:
       t = ''.join(r.text for r in p.runs).strip()
       if p._p.findall('.//' + qn('m:oMath')): seq.append('M')          # 公式
       elif not t: seq.append('E')                                       # 空段
       elif re.match(r'^图\s*[A-Z0-9]', t): seq.append('F')              # 图注
       elif re.match(r'^表\s*[A-Z0-9]', t): seq.append('T')              # 表注
       else: seq.append('P')                                             # 正文
   pos = [i for i, c in enumerate(seq) if c == 'F']
   bad = 0
   for a, b in zip(pos, pos[1:]):
       if 'P' not in seq[a + 1:b]:
           print('FAIL 图注连排：', paras[a].text[:30], '→', paras[b].text[:30]); bad += 1
   print('图连排处数 =', bad, '（必须为 0）')
   ```

2. **前置引导句**：每个图/表出现前，正文叙述中必须有引导句把它嵌进去（获奖句式，直接照用）：`对…进行可视化，其效果如图所示`、`计算结果如表X所示`、`将结果可视化，其效果如图所示`。禁止没有引导、图/表孤零零插入。

3. **后置解读段**：每个图/表之后必须紧跟解读段，以 `观察图X可知` / `由图X可知` / `分析表X可知` 开头；**禁止图后直接跟下一张图或下一节标题**。

4. **结果多时合并为一张多子图**：同一子问题有多组结果时，优先合并成**一张多子图**（`subplots(2,2)` 或 `1×N` 且 `sharex` 统一时间轴），而不是一张张独立图连排。范例：获奖论文"图12 运动者1的关键角度变化"=4子图合并（下肢角度/躯干倾斜角度/肩-髋-膝夹角/大腿与地面夹角），图注一个、解读一段。

5. **解读段内容模板**（照抄结构，禁止一句话带过）：

   ```
   观察图X可以发现，在<阶段1>，<指标>由X变到Y，明显<增大/减小>，说明<物理/模型含义>；
   <阶段2>，<指标>…；<阶段3>，<指标>…。结合<模型/理论>，这一规律说明<结论>。
   ```

   获奖实例（写入正文的参考）："在起跳阶段下肢角度由X°变到Y°，明显减小，说明下肢快速蹬伸后爆发伸展；腾空阶段肩-髋-膝夹角逐渐减小，有明显收腹姿态；落地时下肢角度增加、躯干角度维持在38°，为缓冲做准备。"解读段至少包含：**具体数值变化 + 阶段/趋势规律 + 原因或物理/模型含义**。

**图题与图内容一致性（强制）**：图题必须能被图内元素**逐项验证**——图题写到的每个元素都必须在图中真实存在（"编号标注"→图内必须有编号数字、"曲线"→图内必须有该曲线、"子图"→图内必须有对应子图）。图内只有名称标注时，图题**不得**写"编号标注"。

## 四、关键禁止项

| 禁止项              | 说明                                                |
| ------------------- | --------------------------------------------------- |
| ❌ 斜体             | 全文禁止斜体，包括公式变量、文中引用等全部正体/直立 |
| ❌ 照抄原题         | 问题重述必须用自己的语言重新组织                    |
| ❌ 公式乱码字符     | 解析器不认识的 `\命令` 会原样输出，必须清理或改用已支持的语法 |
| ❌ 表标题在表格下方 | 必须放在表格上方                                    |
| ❌ 图片标题浮空     | 图片标题的位置不能有问题                            |
| ❌ 分页符错误       | 分页用 python-docx，推荐 `last_p.add_run().add_break(WD_BREAK.PAGE)`（`from docx.enum.text import WD_BREAK`，`last_p` 为关键词段/最后一条参考文献段），在关键词后、附录前插入；`doc.add_page_break()` 是独立空段落，上一页恰好写满时会挤出空白页 |
| ❌ 公式未走 OMML | 公式必须调用 tools/omml_builder.py 生成 Word 原生公式，禁止声称"已完成"但公式仍是纯文本 |
| ❌ 首页未独占 | 标题+摘要+关键词必须在第一页，关键词后必须插入分页符，正文从第二页开始。禁止第二页出现摘要 |
| ❌ 跳过任何步骤 | 最终工作流步骤必须全部执行，禁止跳过解析器生成公式、结构验证、LibreOffice 预览等关键步骤 |
| ❌ 图连排 | 多图连续插入且中间无正文讲解（结果多时应合并为一张多子图 2×2/1×N），每张图/表后必须紧跟解读段 |
| ❌ 硬编码结果数字 | 正文/表格结果数字禁止写死字面量（`'15.88'`），必须从结果文件+门面取数；用 `check_numbers.py` 自动校验（每论文从 `tools/check_numbers_template.py` 复制并改写 `derived()`，见二·5"结果数字单一数据源"） |
| ❌ 杜撰数字 | 结果数字查不到时先查证/反馈用户，禁止编造或手填；`check_numbers.py`（模板复制版）Step C 会拦截（退出码 2），不得绕过或改白名单放行 |
| ❌ 杜撰文献 | 编造不存在的出版物条目。AI 最易编成"期刊/书名、主题都真实、看似贴题，而**指定文献+作者+卷期页码是捏的**"（2024 D 题实删案例：王铭文·金长泽《反潜武器系统作战效能分析中的蒙特卡洛方法》舰船电子工程 35(4):34-37,2015——期刊真实、卷期页码与作者系编造，精确标题+作者 0 命中）。提交前对每条外部文献逐条联网核对：搜「标题+作者+卷期」命中 0 即可疑，须核实来源或删除/替换。**格式合规≠真实**——查重、引用落点、格式规范都查不出编造的文献（详见"参考文献真实性排查"） |
| ❌ 文献作者/版次错配 | 条目本身真实（书名/出版社/年份/卷期都对），但**作者列表是另一个版次的署名**。AI 常把不同版次的作者拼到一起（2024 E 题：写"司守奎,孙玺菁 …数学建模算法与应用(第二版)…2015"——"司守奎,孙玺菁"是 2011 **第一版**署名，2015 第二版为司守奎、孙兆亮）。书名/主题真 ≠ 作者真：提交前逐条联网核对**你所写的那个版次**的作者列表，凡"作者+版次"对不上即改（见第五节 20p、十一 说与做"文献作者/版次错配"） |
| ❌ ∑/∏/∫ 缺上下限 | 求和/连乘/积分必须写全上下限（`\sum_{i=1}^{2}`），禁止 `\sum_{i}` 只写下限——缺 `<m:sup>` 时 WPS 渲染成虚线占位框（2026-08-27 确认，非 limLoc 问题） |

## 五、最终检查清单（每次必须执行）

生成最终文件后，**先跑一键校验 `python tools/verify_paper.py 论文.docx [论文.pdf]`（连排/解读/OMML 结构/摘要结构/页均字数，见 20g、20h），再逐条核对以下清单**：

### 正文与格式检查
1. **第一页是否仅含标题+摘要+关键词**，正文是否从第二页开始（关键词后是否有分页符）
2. **第二页及之后是否绝对没有标题、摘要、关键词**（反复确认）
3. 全文是否有残留斜体（`<i>` 标签、`font-style:italic`）
4. **数学公式是否渲染为 Word 原生格式**（双击能否弹出公式编辑界面，**公式中是否有 `\` 字面文本残留**，如 `\cdot` `\sum` 等）
5. **数学单位 `‰` `%` `°` `±` `~` 是否走 OMML**（不是在纯文本中）
6. 表格是否为三线表（**顶线是否真的渲染出来**——渲染后应 3 横线 0 竖线；若缺顶线，检查表头 `tcBorders` 是否误含 `w:top`、`w:tblW` 是否重复）、表标题是否在表格上方
7. 页码是否居中
8. 段落首行是否缩进 2em
9. 图/表是否居中
10. **相邻图/表之间是否有 ≥1 正文段相隔**（图/表禁止连排；图后紧跟解读段，见第三节"图文排布"）
11. 页边距、行间距、各级字号是否符合规范
12. 图表是否连续无遗漏编号
13. 各级标题段间距是否正确（一级12/6pt, 二级10/5pt, 三级8/4pt）
14. 表标题是否加粗、图标题是否不加粗
15. 摘要正文是否左对齐且首行缩进36pt
16. 表标题和图标题行距是否为1.1倍（264）
17. 图片中的文字（坐标轴标签、图例、刻度等）是否不小于 10pt，是否清晰可读
18. **公式是否为原生 OMML**（解压 docx 检查 `word/document.xml` 中 `<m:oMath>` 数量 > 0，块级公式包在 `<m:oMathPara>` 中，`<m:sSub>`/`<m:nary>`/`<m:f>` 等结构数量符合预期）
19. **公式中是否有残留 `\` 字面文本**（剥离 `<m:oMath>` 后扫描 `w:t`，或渲染后目视/OCR——若有 `\frac` 等，说明解析器遇到不认识的命令，须扩展解析器或改用已支持的语法）
20. **docx 是否完整可打开**（python-docx 重新打开无异常；LibreOffice 转 PDF 无报错）
20b. **封面高度是否安全**（首页内容带底端距下边距余量 ≥40px@150dpi，量化脚本见第二节"首页"的"封面高度陷阱"）。若出现"Word 里首页正常、PDF 里关键词独占第 2 页"，判定为满页溢出 → 精简摘要文字（保留全部数值与结论）后重转重测
20c. **文字详细度是否达标**：每个解读段通过内容要素门（含 具体数值变化 + 阶段/趋势规律 + 原因/机理，缺一 FAIL）、无注水黑名单表述；全文"观察图X/由图X可知/分析表X可知/由表X可知"解读短语总数 ≥ 图/表提及总数。正文页平均字符数仅作密度诊断（<1800 提示补解读，不单凭字数 FAIL）（判据见第二节 5"文字详细度"）
20d. **结果数字单一数据源是否 PASS**：论文目录 `check_numbers.py`（由 `tools/check_numbers_template.py` 复制、改写 `derived()` 而成，见二·5）退出码 0（Step B 漂移扫描：结果集合无字面量残留）
20e. **反杜撰是否 0 命中**：同上脚本 Step C 通过（结果语境数字均在白名单，无杜撰）
20f. **每个 `<m:nary>` 是否有 `<m:sup>`**：`verify_paper.py` 的 OMML 门已按"**直接子节点**"逐个 `<m:nary>` 判定（**嵌套感知**：内层∑ 套在外层 `<m:e>` 里、或 e 深处 `W^{1/2}` 的上标，都不会被误当作"该 ∑ 有上标"——2026-09 修掉旧"非贪婪正则+段内含 sup"的盲区），生成后无需手工解压抽查。仍可解压 `word/document.xml` 复核每个 `<m:nary>` 均含 `<m:sup>`（求和上下限齐全）；缺上标 WPS 渲染虚线框。回归见 `tools/test_nary_sup.py`
20g. **一键校验是否运行**：`python tools/verify_paper.py 论文.docx [论文.pdf]` 输出全 PASS（连排 0 处、解读短语 ≥ 结果图/表数、每个 `<m:nary>` 有 `<m:sup>`、公式外无 `\` 残留；页均字数为密度诊断仅供人工参考，不 FAIL）
20h. **摘要结构是否通过机器检查**：`verify_paper.py` 输出的摘要结构项 PASS（摘要段数 = 题量 + 2：开头 + 每问各一段 + 结尾；每个"针对问题 N"段编号连续 1..N；无"针对问题 X、Y"合并段；中文字符数 700~800 为 INFO 供参考，不 FAIL）
20i. **降 AI 味软门是否扫描**：`verify_paper.py` 输出「文风建议」（R1 裸图导语 / R2 强调式开句堆叠 / R3 段尾拔高，WARN/INFO，**不 FAIL、不影响退出码**）——命中项按第十节改写后复扫到 0 条为佳；不改也能交差（风格属主观，作者定夺）
20j. **图/表编号是否全部整数**：`verify_paper.py` 输出「图/表编号整数」PASS（无「第 1.0 图」「图 4.0」小数图号）。若 FAIL 用 `第X.N图/表` 正则全文替换回整数（图号 = 图序，表号 = 表序，不得带小数）
20k. **正文引用落点是否齐全**：`verify_paper.py` 输出「引用落点」PASS（参考文献每条 `[k]` 均在正文出现至少一次）。若 FAIL 在正文相应"理论依据/算法引用"处补 `[k]`，禁止参考文献孤挂
20l. **可复现性是否通过**：`verify_paper.py`（三参：docx、pdf、论文目录）输出「可复现性」PASS——生成/求解脚本不含机器绝对路径（`C:\Users\`、`D:\tool\`）、`omml_builder.py` 随产物捆绑（越层 `sys.path.insert` 指向技能仓库 tools 即违规）
20m. **概率分布参数名称是否与术语一致**：`verify_paper.py` 输出「截尾术语」PASS（无「截尾...均值/标准差/方差」）。题设给的是**截断前**分布的参数，就不得称作**截尾分布**的矩——例：D 题 `h0/σz` 是截断前正态的位置/尺度参数（`E[Z]≈165.575, SD≈29.835` 是截断后方能算的矩，别标成 `h0/σz`）。凡涉及截断/截尾、混合、分点分布，逐一核对参数的真实含义再落笔
20n. **交付物是否由当前源码刚构建**：改动任一生成/求解脚本（`build_paper_*.py`、`make_figs.py`、`solve.py`、`paper_results.py`、`omml_builder.py`）后，`docx/pdf` 是否由**这次**源码重跑整链得到（而非旧构建残留）？判据：旧表述回归核对 0 命中 + 本次源码新表述已在产物中出现。**源码是事实源，docx 是产物**——默认当前 docx 是旧的，先重建再校验（见规则 10）
20o. **外审/用户反馈是否回归核对**：收到审计/评审/用户具体意见后，是否建了「反馈→旧句→应改成→重建后产物检索」回归表，并逐条验证旧句 0 命中 / 新句已出现？核对完再跑 verify_paper / check_numbers（都只对这次新产物）。只"改源码忘重建、拿旧 docx 校验"必然导致第二份报告照旧报"仍错"（见规则 10 细则）

## 七、本次实战补充规范（2026-08-03）

### 摘要格式（强制）

摘要必须按照以下结构分段撰写：

1. **开头段**：2-3句话，3-5行，概括全文背景与总体框架；若论文含多个递进模型，**在此点名**（"依次建立 A、B、C 模型"），让评阅第一眼看到关键建模
2. **每个问题各一段**（段落数 = 实际题量，如赛题 4 个小问则写 4 段）：解决了什么问题 + 应用了什么方法 + 得到了什么结果
3. **结尾段**：总结全文 / 介绍亮点 / 对类似问题进行推广
4. **关键词**：用两个空格分隔，不用分号。格式：关键词1 关键词2 关键词3 关键词4

**三条补充规则（2026-09 增补，逐条强制）**：

- **每个问题各一段，禁止合并**：即使两个小问共用同一模型框架，也不能合成一段（禁止"针对问题 X、Y，……"）；段落数 = 实际题量 + 2（开头 + 每问各一段 + 结尾）。两问合一段会把后一问的建模贡献在摘要里埋没。
- **关键建模问题必须"立模型"**：若某问的核心贡献是新增/扩展建模（如"增加第二个突水点 → 双源水流漫延"），该段必须以模型名称作主语明确写出（"建立 ×× 模型"），禁止只用场景描述（"在……发生的场景下"）一笔带过。评阅只读摘要时，靠模型名识别本题关键，模型名不出现即视为没建。
- **每段骨架 = 针对问题 X + 怎么分析 + 怎么做 + 结果是什么**：禁止以复述题设开头（延迟值/场景参数罗列）；结果必须给数值（到达时刻/覆盖率/误差等），不允许只写"方案可行"。

> **反面案例（2026-09 D 题实战）**：摘要把"问题 3、4"合成一段，双源水流漫延模型只一句话带过、其余全是问题 4 的重规划流程。评委反馈："问题 3 是在 1、2 的基础上增加了一个突水点，建立两个突水点的流动蔓延模型才是关键，评委可能从摘要里就判定你没有。"拆分后问题 3 单独成段、以"建立双突水点水流漫延模型"立出，且每段以"针对问题 N"开头、给结果数值，即通过机器检查（verify_paper 摘要结构项）。

> **降 AI 味**：摘要每段除满足上述骨架外，还要过第十节 T2/T6 检查——段尾自夸（"…兼顾了…""…具备较强的…"）、以复述题设开头都是 AI 味，须改写。

### 数学公式（强制 — 最高优先级）

**🚨 警告**：这是论文最容易出问题的地方。历史上 Claude 多次在此处偷懒，导致公式显示为纯文本乱码。**你必须严格按照以下每一步执行，不得跳过、不得简化、不得"优化"。**

- **绝对必须**使用 Word 原生公式编辑器格式（OMML/OMath），严禁使用纯文本+上下标凑合
- 公式字体 Times New Roman，全部正体（**禁止斜体**），不加编号
- 字号 11pt，居中
- **验证方法**：解压 docx 检查 `word/document.xml` 中 `<m:oMath>` 数量 > 0；LibreOffice 转 PDF 后目视/OCR 抽查上下标、求和、分数是否正常渲染

#### 范围：块级公式 + 段落内嵌符号

不仅块级公式（数量取决于论文内容，通常 20~40 个），**段落中出现的任何数学符号、上下标也必须走 OMML**。例如正文中写到 `f_i`、`n(t)`、`m_{ij}`、`L_c`、`TFR`、`SRB` 等，不能写成纯文本，必须用 Word 原生公式渲染。

#### 技术路线：调用解析器直接生成 OMML（唯一推荐）

> **为什么不用 Word/WPS COM BuildUp**：`BuildUp()` 依赖微软 MS Word。本机是 **WPS Office**（`Word.Application` COM 实际指向 `wps.exe`），实测 `OMaths.BuildUp()` 不会真正构建公式——只把文本包成空公式框或原样保留 `x_12`，**`m:sSub` 数量为 0**（WPS 官方社区亦有同样反馈）。且即使装了真 Word，COM 自动化也有注册表抢占、版本差异、静默失败等坑。因此本技能统一改为：**用配套解析器 `tools/omml_builder.py` 在 python-docx 内部把公式字符串直接构建成 `<m:oMath>/<m:sSub>/<m:nary>` XML 写入段落**——跳过所有 COM，任何机器都能跑，产出的仍是 Word 原生公式，双击可编辑。

**工具位置**：`tools/omml_builder.py`（相对本 SKILL.md 所在目录，**本技能唯一权威版本**）。使用前先确认该文件存在；**若缺失，必须直接按本文档"技能自我完善规则"重新实现并测试，绝对禁止从任何旧任务目录复制**——旧任务目录里可能残留旧版解析器，缺本次新增的低频符号、标准命令、字体样式、`x_\alpha` 等全部语法，会让公式退化成旧能力（任务目录随时可能被删除，可复用的东西只会放本技能目录或其同级，AI 读技能时不需要去其他文件夹找材料）。生成器代码中必须**先把本文件复制到论文程序目录**，再用 `sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))` 本地导入（见第六节 Step 1 模板）。**禁止**在生成脚本里写技能仓库路径或本机绝对路径——那会同时触发可复现性门（规则 ⑧：机器绝对路径 + 越层 `sys.path.insert`），且换机后 `ModuleNotFoundError`。

**整体流程（不可省略任何步骤）**：

```

    → 结构验证 + LibreOffice 预览确认
```

#### Step 1 — 用解析器写入公式

**标记符**：正文/表格中用 `$$...$$` 包裹公式（与普通文字混排时用 `split_formula_marks()` 拆分）。块级公式单独一段。

**Python 辅助函数模板（照抄，按需调整字体/字号）**：

```python
import sys, os
# 【可复现性强制 · 勿改】先把技能目录 tools/omml_builder.py 复制到本论文程序目录，再本地导入。
# 禁止写技能仓库路径或本机绝对路径（绝对路径＝以盘符或 /Users、/home 开头的路径）——会同时
# 触发 verify_paper.py 可复现性门的两条判据（机器绝对路径 + 越层 sys.path.insert）并换机报错。
# 解释器路径只写在本机命令行里，不写进脚本。
sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
from omml_builder import build_omath, split_formula_marks
from docx.shared import Pt, Cm
from docx.enum.text import WD_ALIGN_PARAGRAPH
from docx.enum.table import WD_TABLE_ALIGNMENT
from docx.oxml.ns import qn
from docx.oxml import parse_xml

MNS = 'http://schemas.openxmlformats.org/officeDocument/2006/math'
WNS = 'http://schemas.openxmlformats.org/wordprocessingml/2006/main'   # 模块级，供下方三线表配方 % WNS 使用

def FI(text):
    """内嵌公式：$$...$$ 标记，构建时由解析器转为 OMML。
    正文中所有数学符号/上下标/希腊字母/数学单位必须走此函数。
    示例：FI('x_{11}')、FI('TFR')、FI('‰')、FI('%')"""
    return '$$' + text + '$$'

def _set_math_para_font(p, size_pt):
    """设置段落标记字号，使该段内 OMML 公式以指定字号渲染"""
    WNS = 'http://schemas.openxmlformats.org/wordprocessingml/2006/main'
    pPr = p._p.get_or_add_pPr()
    pPr.append(parse_xml(
        '<w:rPr xmlns:w="%s">'
        '<w:rFonts w:ascii="Times New Roman" w:hAnsi="Times New Roman" w:eastAsia="宋体"/>'
        '<w:sz w:val="%d"/>'
        '</w:rPr>' % (WNS, int(size_pt * 2))))

def _add_mixed_runs(p, text, font_name, size_pt, bold=False):
    """把含 $$...$$ 的文本写入段落：普通文字为文本 run，$$...$$ 解析为内嵌 OMML"""
    for kind, seg in split_formula_marks(text):
        if kind == 'm':
            p._p.append(build_omath(seg))
        else:
            run = p.add_run(seg)
            run.font.name = font_name
            run._element.rPr.rFonts.set(qn('w:eastAsia'), font_name)
            run.font.size = Pt(size_pt)
            run.font.bold = bold

def add_formula(doc, text):
    """块级公式：整段为 OMML，居中，Times New Roman 11pt"""
    from docx.enum.text import WD_ALIGN_PARAGRAPH
    p = doc.add_paragraph()
    p.alignment = WD_ALIGN_PARAGRAPH.CENTER
    omp = parse_xml('<m:oMathPara xmlns:m="%s"/>' % MNS)
    omp.append(build_omath(text))
    p._p.append(omp)
    _set_math_para_font(p, 11)
```

- **遇到解析器不认识的 `\命令`**：会在公式里原样输出 `\命令`。此时按"技能自我完善规则"扩展 `omml_builder.py`（补 LATEX_SYMBOLS 或新增 handler），并在 `test_omml.py` 补一条测试，再回写文件头注释

**重要规则**：
- 一个 `$$...$$` 包裹一个完整公式（块级）或一个符号（内嵌）
- **禁止**在 `FI()` 中放纯文本（如 `FI("TFR")` 正确，`FI("总和生育率")` 错误）
- 块级公式多行时分行写，一个公式一段
- 解析器支持 `\frac`、矩阵等复杂结构，**不需要**再手动改用斜杠 `a/b` 之类凑合
- **块级 vs 行内**：块级公式**必须**用 `add_formula()`（包 `<m:oMathPara>` 居中）；行内符号用 `FI()` 交给 `_add_mixed_runs`（`build_omath()` 直接挂段落，**不包** oMathPara）。混用会导致块级公式不居中
- **∑/∏/∫ 必须给全上下限**：`\sum_{i=1}^{2}`、`\int_{0}^{1}`、`\prod_{k=1}^{n}`；**禁止** `\sum_{i}`、`\prod_{k}` 这类只写下限的写法。只写下限时生成的 `<m:nary>` 缺 `<m:sup>`（上标），WPS 会把求和号渲染成**虚线占位框**（2026-08-27 已确认，非 limLoc 设置问题）；生成后由 `verify_paper.py` 的 OMML 门自动检查（按"**直接子节点**"判定、嵌套感知——内层∑ 套外层 `<m:e>`、或 `W^{1/2}` 上标不会误判，见 `tools/test_nary_sup.py`；2026-09 修掉旧"段内含 sup"盲区），也可解压 docx 按检查清单 20f 复核每个 `<m:nary>` 均有 `<m:sup>`
- **`build_omath()` 只接收纯公式字符串（不含 `$$`）**：`$$...$$` 由 `split_formula_marks()` 剥离后进入解析器。直接把 `$$...$$` 完整串传给 `build_omath()` 会把 `$$` 当普通 `$` 字符混进公式（解析器已加兜底自动剥离首尾 `$$`，但正确写法是传纯公式）

#### 数学单位与特殊符号（必须走 OMML）

以下符号在论文中频繁出现，**必须**用 `FI()` 包裹，不能写成纯文本：

| 符号 | 含义 | 使用场景 | 正确写法 | 错误写法 |
|------|------|---------|---------|---------|
| `‰` | 千分号 | 生育率、死亡率单位 | `FI("‰")` | 直接写 `‰` 或 `%` |
| `%` | 百分号 | 城镇化率、占比、抚养比 | `FI("%")` | 直接写 `%` |
| `°` | 度（角度） | 经纬度等 | `FI("°")` | 直接写 `°` |
| `±` | 正负号 | 误差范围 | `FI("±")` | 直接写 `±` |
| `~` | 约等/数量级 | 约 13.55 亿 | `FI("~")` | 直接写 `~` |

**为什么**：这些符号如果写成纯文本，字体是宋体/正文体，与数学公式的 Times New Roman 不一致，且不与前面的数字联动。放入 OMML 后，字体统一为 Times New Roman，且与前面的数字变量属于同一个公式域。

**使用示例**：

```python
# 正确：‰ 必须用 FI() 包裹
add_body(doc, '年龄别生育率 ' + FI('f_i') + ' 的单位为' + FI('‰') + '（千分比）。')

# 正确：% 必须用 FI() 包裹
add_body(doc, '城镇化率从 2005 年的 44.9' + FI('%') + ' 持续上升至 2050 年的 56.5' + FI('%') + '。')

# 错误：直接写纯文本 ‰ 或 %
add_body(doc, '死亡率单位为‰。')           # ‰ 是纯文本，不是 OMML
add_body(doc, '城镇化率达到56.5%。')        # % 是纯文本，不是 OMML
```

**注意**：`‰` 和 `%` 作为**纯中文叙述中的标点符号**使用时（如"约占56.5%。"中的句号后的%），可以保持纯文本。但作为**数学/统计数值的单位**时（如"56.5%"作为数据），必须走 `FI()`。

#### 🚨 公式渲染问题诊断（遇到问题先查这里）

| 症状 | 可能原因 | 解决方案 |
|------|---------|---------|
| 公式中残留 `\frac` 等字面 `\` 文本 | 解析器不认识的 `\命令` | 补全 LATEX_SYMBOLS 或新增 handler（见"技能自我完善规则"），或在公式里改用已支持的语法 |
| `<m:oMath>` 数量为 0 | 没调用解析器，公式写成了纯文本 | 检查正文是否用 `$$...$$` + `build_omath()` |
| 公式字体/字号不对 | 段落标记 `w:rPr` 没设 | 用 `_set_math_para_font()` 设置 Times New Roman + 字号 |
| 下标没变成真下标 | 简单写法用了 `x_11` 而非 `x_{11}` | 简单写法下标必须用花括号：`x_{11}` |
| 块级公式未居中 | 没用 `oMathPara` | 块级公式必须包 `<m:oMathPara>` 并居中 |
| 中文乱码 | 源文件编码问题 | 源 .py 文件保持 UTF-8；python-docx 本身处理中文无碍 |
| 公式中出现 `?` 占位 | 公式某参数为空（如 `\frac{a}{}`、`x_{}`、`\sqrt{}`、`\sum_{}^{}`） | 修正公式补上参数内容。**正常公式不会出现 `?`**，出现即说明公式写错了 |
| 交互式 WPS 中 ∑/∏/∫ 等运算符**上方出现虚线框/占位框**（WPS COM 导出 PDF 反而正常） | OMML `<m:nary>` **缺少 `<m:sup>` 上标元素**——公式写成了 `\sum_{j}` 而非 `\sum_{j=1}^{n}`（**不是 `<m:limLoc>` 的问题**） | 公式改为 `\sum_{j=1}^{n}` 给全上下限后重新生成 docx |

##### 🚨 公式渲染异常 → 快速定位方法论（2026-08-27 实测，遇到渲染问题先读这里）

当用户报告公式在 Word/WPS 里显示异常（虚线框、缺上下标、符号不对）时，**按以下顺序排查，禁止先怀疑缓存/渲染引擎/limLoc**：

1. **先查数据，不猜环境**：解压 docx 的 `word/document.xml`，定位到用户指出的那一段，逐个检查每个 `<m:nary>` 是否有 `<m:sub>` 和 `<m:sup>`，上下标文本是否完整（`j=1` / `7` / `16`）。
2. **采纳用户线索**：用户说"只有这一个公式""在哪两段文字之间"——这是最高价值的定位信息，直接跳到该段检查，不要全篇撒网。
3. **对比同文件正常公式**：同一份文件里渲染正常的 nary 与异常的那个对比 `sub`/`sup`/`naryPr`，差异通常一眼显形。
4. **正确归因**：**「∑ 上方虚线框」≈「缺 `<m:sup>` 或上标为空」**——WPS/Word 把空上标槽渲染成虚线占位框。历史上一度误归因于 `<m:limLoc m:val="undOvr"/>`，证据是被"缺 sup"混淆的，**勿再犯**；`naryPr` 保持只含 `<m:chr>` 即可。
5. **验证**：改完重新生成后，用 WPS COM `ExportAsFixedFormat` 导出 PDF，`pdftotext` 能提取出上标数字（如 `16`）即渲染正常——虚线框提不出文字。LibreOffice 预览同样可用。

| 偷懒方式 | 为什么错误 | 正确做法 |
|---------|-----------|---------|
| 公式写成纯文本/Unicode 上下标（`β₁`、`R²`、`x̄`） | 不是 Word 原生公式，老师一查就穿帮 | 必须用 `$$...$$` + 解析器转 OMML |

### 表格（强制 — 三线表）

- 只保留三条横线：顶线1.5pt粗、表头下线0.75pt细、底线1.5pt粗
- **删除全部竖线**
- **删除单元格之间所有分隔横线**
- 表标题放在表格**上方**，居中排版
- python-docx 实现：表格级 `tblBorders` 设顶线/底线 `w:sz="12"`（1.5pt），`left/right/insideH/insideV` 为 `none`；表头行每个单元格 `tcBorders` 设 `w:bottom` `w:sz="6"`（0.75pt）。完整配方**内联如下（直接照抄，勿去任务目录找）**。
- ⚠️ **实测坑（2025-CUMCM E / 2026-09-02 复现验证，必须遵守）**：
  - **表头单元格 `tcBorders` 禁止出现 `w:top`**（哪怕 `w:val="none"` 也会抹掉顶线）——单元格级边框优先级高于表格级，`w:top val="none"` 会把表格顶线盖掉，三线表渲染成 2 线表。表头 `tcBorders` 只写 `left=none / bottom=单线 / right=none`。
  - **追加固定 `w:tblW` 前必须先删除已有 `w:tblW`**——`table.autofit = False` 已自动写入一个 `<w:tblW w:w="0" w:type="auto"/>`，再 append 固定宽度会残留两个 `w:tblW`，Word 只取第一个（auto），固定宽度失效。先 `for elem in tblPr.findall(qn('w:tblW')): tblPr.remove(elem)` 再 append。
  - **表格单元格段落必须显式覆盖行距**：python-docx 模板 `docDefaults` 自带"段后 10pt + 1.15 倍行距"，正文段覆盖了、**单元格没覆盖 → 整表行高虚胖（~35pt/行）、长表放不满一页被迫跨页**。`_fill_cell` 必须设 `space_before/space_after = Pt(0)`、`line_spacing = 1.0`（下方配方已内置，勿删）。
  - **三线表严禁跨页断裂**：表头+正文行被页面切断是典型版式违规。长表给表头行设 `tblHeader` 重复表头 + 每行 `cantSplit`；短表（≤几行）用 `keep_with_next` 让整表成块，放不下则整体移到下一页，绝不半截断开。⚠️ **"整表成块"的 keep_with_next 只设到表格行/表题，禁止设到每个单元格内部段落**（`for row in table.rows: for cell in row.cells: for para in cell.paragraphs: para.paragraph_format.keep_with_next=True`）——单元格 keepNext 会把整表与后续所有表/图注/正文链式绑定，Word 推整块到下一页撑出空白页（2024-E 实测第 5/6/7/20 页空白；正确做法见"页面结构"分页根因#2）。
  - **表标题/图标题段前段后参数不同，不可共用一组**：表标题 前 8pt/后 4pt、图标题 前 4pt/后 8pt（见格式总表）。`add_caption` 必须按"表/图"分开传参，不可图注表注统一 `(4,8)`。

```python
# 前置：doc = Document()；模块级 WNS（见第六节 Step 1 模板）；所需 import 已在第六节 Step 1 模板补全
#（from docx.shared import Pt, Cm；from docx.enum.text import WD_ALIGN_PARAGRAPH；
#  from docx.enum.table import WD_TABLE_ALIGNMENT）。_fill_cell 定义在下方（复用 _add_mixed_runs，bold 参数由模板支持）。
def _fill_cell(cell, val, font_name, size_pt, bold):
    """填充单元格，支持 $$...$$ 内嵌公式"""
    cell.vertical_alignment = 1
    p = cell.paragraphs[0]
    p.alignment = WD_ALIGN_PARAGRAPH.CENTER
    # 关键：必须显式覆盖 docDefaults 的"段后10pt+1.15倍行距"，否则单元格段落继承后每行被撑到 ~35pt，
    # 长表放不满一页 → 三线表跨页断裂（2026-09-02 复现的版式违规根因，勿删）
    p.paragraph_format.space_before = Pt(0)
    p.paragraph_format.space_after = Pt(0)
    p.paragraph_format.line_spacing = 1.0
    _add_mixed_runs(p, str(val), font_name, size_pt, bold)


def make_three_line_table(headers, data_rows, col_widths_cm=None):
    """三线表：顶线1.5pt、表头下线0.75pt、底线1.5pt，无竖线，宽14cm居中"""
    table = doc.add_table(rows=1 + len(data_rows), cols=len(headers))
    table.alignment = WD_TABLE_ALIGNMENT.CENTER
    table.style = 'Table Grid'
    table.autofit = False
    tbl = table._tbl
    tblPr = tbl.tblPr
    # 坑①：autofit=False 已生成 <w:tblW w:w="0" w:type="auto"/>，必须先删除再追加固定宽度，
    # 否则残留两个 w:tblW、Word 只取第一个（宽度失效）
    for elem in tblPr.findall(qn('w:tblW')):
        tblPr.remove(elem)
    tblPr.append(parse_xml('<w:tblW xmlns:w="%s" w:w="7938" w:type="dxa"/>' % WNS))
    if col_widths_cm:
        for i, w in enumerate(col_widths_cm):
            for cell in table.columns[i].cells:
                cell.width = Cm(w)
    for i, h in enumerate(headers):
        _fill_cell(table.rows[0].cells[i], h, '宋体', 10, True)
    for ri, row_data in enumerate(data_rows):
        for ci, val in enumerate(row_data):
            _fill_cell(table.rows[ri + 1].cells[ci], val, '宋体', 10, False)
    # 三线表边框：顶线/底线 1.5pt(sz=12)，其余 none
    borders_xml = '''
    <w:tblBorders xmlns:w="%s">
      <w:top w:val="single" w:sz="12" w:space="0" w:color="000000"/>
      <w:left w:val="none" w:sz="0" w:space="0" w:color="auto"/>
      <w:bottom w:val="single" w:sz="12" w:space="0" w:color="000000"/>
      <w:right w:val="none" w:sz="0" w:space="0" w:color="auto"/>
      <w:insideH w:val="none" w:sz="0" w:space="0" w:color="auto"/>
      <w:insideV w:val="none" w:sz="0" w:space="0" w:color="auto"/>
    </w:tblBorders>
    ''' % WNS
    for elem in tblPr.findall(qn('w:tblBorders')):
        tblPr.remove(elem)
    tblPr.append(parse_xml(borders_xml))
    # 表头下线 0.75pt(sz=6)
    # 坑②：tcBorders 禁止出现 w:top（哪怕 val="none"）——单元格级边框优先级高于表格级，
    # 会把表格顶线盖掉，三线表变 2 线表。只保留 left=none / bottom=单线 / right=none。
    for cell in table.rows[0].cells:
        tcPr = cell._tc.get_or_add_tcPr()
        tcBorders = parse_xml('''
        <w:tcBorders xmlns:w="%s">
          <w:left w:val="none" w:sz="0" w:space="0" w:color="auto"/>
          <w:bottom w:val="single" w:sz="6" w:space="0" w:color="000000"/>
          <w:right w:val="none" w:sz="0" w:space="0" w:color="auto"/>
        </w:tcBorders>
        ''' % WNS)
        tcPr.append(tcBorders)
    return table
```

- **分页符**：python-docx 插入。推荐把分页符**追加到上一段末尾**：`from docx.enum.text import WD_BREAK; last_p.add_run().add_break(WD_BREAK.PAGE)`（`last_p` = 关键词段 / 最后一条参考文献段）。`doc.add_page_break()` 是独立空段落，上一页恰好写满时会被挤到下一页顶部产生空白页，仅在确信上一页未满时才可用。HTML 的 `page-break-before` CSS 在 Word 中不生效，必须用 python-docx 的分页符。

### 9.2 OMML XML 基本结构（只掌握最常见元素）

一个 OMML 公式的基本骨架：

```xml
<m:oMath>
  <!-- 普通文本/变量 -->
  <m:r><m:t>TFR=</m:t></m:r>

  <!-- 求和/积分等大算符（nary） -->
  <m:nary>
    <m:naryPr><m:chr m:val="∑"/></m:naryPr>
    <m:sub><m:r><m:t>i=15</m:t></m:r></m:sub>    <!-- 下标 -->
    <m:sup><m:r><m:t>49</m:t></m:r></m:sup>       <!-- 上标 -->
    <m:e>                                          <!-- 求和表达式 -->
      ...被求和的变量...
    </m:e>
  </m:nary>

  <!-- 下标（sSub） -->
  <m:sSub>
    <m:e><m:r><m:t>f</m:t></m:r></m:e>            <!-- 基变量 -->
    <m:sub><m:r><m:t>i</m:t></m:r></m:sub>         <!-- 下标 -->
  </m:sSub>

  <!-- 上标（sSup） -->
  <m:sSup>
    <m:e><m:r><m:t>x</m:t></m:r></m:e>
    <m:sup><m:r><m:t>2</m:t></m:r></m:sup>
  </m:sSup>

  <!-- 上下标（sSubSup） -->
  <m:sSubSup>
    <m:e><m:r><m:t>n</m:t></m:r></m:e>
    <m:sub><m:r><m:t>i</m:t></m:r></m:sub>
    <m:sup><m:r><m:t>t</m:t></m:r></m:sup>
  </m:sSubSup>

  <!-- 括号/分隔符（d）—— 常见畸形来源 -->
  <m:d>
    <m:dPr>
      <m:begChr m:val="{"/>
      <m:endChr m:val="}"/>
    </m:dPr>
    <m:e>...被包裹的内容...</m:e>
  </m:d>

  <!-- 分数（f） -->
  <m:f>
    <m:num><m:r><m:t>a</m:t></m:r></m:num>
    <m:den><m:r><m:t>b</m:t></m:r></m:den>
  </m:f>
</m:oMath>
```

**关键规则**：
- `m:nary` 的 `m:sub` 和 `m:sup` 直接放文本，**不需要**再用 `m:d` 包裹
- `m:e` 是表达式容器，求和变量必须放在这里
- `m:d` 是括号/分隔符，**不要**用它来包裹上下标内容
- `m:sSub` 专门用于带下标的变量（如 `f_i`）

### 9.3 🚨 常见 OMML 畸形与修复对照表

以下是最常见的公式畸形及其修复方法：

| 症状 | 原因 | 错误 XML 特征 | 修复方法 |
|------|------|-------------|---------|
| 求和下标显示 `{i=15}`（有大括号） | 多余 `m:d` 包裹下标 | `<m:sub><m:d><m:dPr><m:begChr m:val="{"/>...` | 去掉 `m:d` 层，直接保留 `<m:sub><m:r><m:t>i=15</m:t></m:r></m:sub>` |
| 求和上标显示 `{49}`（有大括号） | 多余 `m:d` 包裹上标 | `<m:sup><m:d><m:dPr><m:begChr m:val="{"/>...` | 去掉 `m:d` 层，直接保留 `<m:sup><m:r><m:t>49</m:t></m:r></m:sup>` |
| 求和变量 `f` 在上标位置 | `f` 被放在了 `m:sup` 内部而非 `m:e` | `<m:sup>...49</m:sup><m:r><m:t>f</m:t></m:r>` | 将 `f` 移到 `<m:e>` 下 |
| 缺少 `f_i` 的下标 `i` | 没有用 `m:sSub` 包裹 | `<m:e><m:r><m:t>f</m:t></m:r></m:e>` | 改为 `<m:e><m:sSub><m:e><m:r><m:t>f</m:t></m:r></m:e><m:sub><m:r><m:t>i</m:t></m:r></m:sub></m:sSub></m:e>` |
| 公式整体被 `m:oMathPara` 包裹 | 正常（段落级公式容器） | `<m:oMathPara><m:oMath>...</m:oMath></m:oMathPara>` | 保留 `m:oMathPara`，只修改内部 `m:oMath` |
| 公式中残留 `\cdot` 字面文本 | 旧流程用 `\` 命令且未转为 Unicode 字符 | 文本内容是 `\cdot` 而非 `·` | 替换为 Unicode 字符 `·`（U+00B7） |

**标准正确结构示例**（`TFR = ∑_{i=15}^{49} f_i`）：

```xml
<m:oMath>
  <m:r><m:t>TFR=</m:t></m:r>
  <m:nary>
    <m:naryPr><m:chr m:val="∑"/></m:naryPr>
    <m:sub><m:r><m:t>i=15</m:t></m:r></m:sub>
    <m:sup><m:r><m:t>49</m:t></m:r></m:sup>
    <m:e>
      <m:sSub>
        <m:e><m:r><m:t>f</m:t></m:r></m:e>
        <m:sub><m:r><m:t>i</m:t></m:r></m:sub>
      </m:sSub>
    </m:e>
  </m:nary>
</m:oMath>
```

### 9.4 🚨 docx 重新打包规则（零容忍）

修改完 `document.xml` 后，重新打包成 docx 时必须遵守以下规则，**违反任何一条都会导致文件损坏**：

| 规则 | 原因 | 正确做法 |
|------|------|---------|
| **zip 路径用反斜杠 `\`** | Word 不认正斜杠 `/` 路径 | Python `zipfile.writestr(backslash_name, data)`，其中 `backslash_name = original_name.replace('/', '\\')` |
| **保留所有文件** | 缺少 `[Content_Types].xml` 则 Word 无法识别文件类型 | 解压时保留所有文件，打包时全部写回 |
| **用 Python zipfile** | PowerShell `Compress-Archive` 自动用 `/` 且无法控制 | 用你的 Python 解释器执行 zipfile 打包 |
| **打包后验证** | 确保文件可打开 | 先 `unzip -t`，再用 LibreOffice 转换测试 |

**Python 打包模板（必须直接照抄，不可修改）**：

```python
import zipfile

src_docx = r'原文件路径.docx'
dst_docx = r'输出文件路径.docx'

# 读取原 docx 的所有条目
with zipfile.ZipFile(src_docx, 'r') as zin:
    entries = [(info.filename, zin.read(info.filename)) for info in zin.infolist()]

# 用反斜杠路径重新打包
with zipfile.ZipFile(dst_docx, 'w', zipfile.ZIP_DEFLATED) as zout:
    for name, data in entries:
        # 关键：将正斜杠替换为反斜杠
        new_name = name.replace('/', '\\')
        zout.writestr(new_name, data)

# 验证
with zipfile.ZipFile(dst_docx, 'r') as z:
    assert not z.testzip(), 'ZIP 完整性检查失败！'
    print('OK: 所有条目已用反斜杠路径打包')
```

**验证命令**：

```bash
# 1. 检查 zip 完整性
unzip -t "输出的docx路径"

# 2. 用 LibreOffice 转换测试（可打开则文件有效）
soffice --headless --convert-to pdf --outdir /tmp "输出的docx路径"
```

### 9.5 失败诊断

| 症状 | 原因 | 解决方案 |
|------|------|---------|
| Word 打不开，提示文件损坏 | zip 路径用了正斜杠 `/` | 用 Python zipfile 重打包，路径用反斜杠 `\` |
| Word 打不开，提示内容错误 | 缺少 `[Content_Types].xml` | 解压时保留原文件全部条目，不要只保留 document.xml |
| 公式仍显示畸形（大括号还在） | OMML XML 修改不正确 | 重新检查 `m:d` 是否已去除，变量是否在 `m:e` 下 |
| LibreOffice 能打开但公式符号乱码 | 字体缺失或编码问题 | 确认 `<m:t>` 中的文本没有乱码，字体设为 Times New Roman |
| 修复后公式位置偏移/段落错乱 | 修改 XML 时改变了文档结构 | 只修改 `m:oMath` 内部，不要动外层 `w:p` 段落结构 |

### 典型场景：TFR 公式修复完整步骤

以本次实战为例，修复 `TFR = ∑_{i=15}^{49} f_i` 公式的完整流程：

```
1. 解压：unzip 原论文.docx -d 临时目录
2. 打开 word/document.xml
3. 搜索包含 ∑ 的 <m:oMath> 段落
4. 找到畸形结构（多余 m:d 包裹上下标 + f 在 m:sup 内 + 缺少 f_i）
5. 用 9.3 节的标准正确结构替换
6. 用 Python zipfile 重打包（路径用反斜杠）
7. 验证：unzip -t + LibreOffice --headless --convert-to pdf
8. 交付给用户
```

## 十、文风与"降 AI 味"写作规范（2026-09-02 增补）

> **反 AI 味 ≠ 变口语，也 ≠ 冷冰冰**。目标三分法：**专业**（有具体数值、有因果机制、结论带限定条件）、**不空泛自夸**（把形容词换成可核验事实）、**不口语**（禁讲解腔）。AI 味 = 模板化结构 + 泛化自夸 + 空修辞的"缝合"，最常出现在摘要每段、图表解读段、ch7 评价节。
> 机器已能软门抓 R1/R2/R3（`verify_paper.py`「文风建议」WARN/INFO，不 FAIL，不影响退出码）；口语（讲解腔）与空洞技术断言（T3）属主观项，本轮靠本节写作期规则 + 判读三问人工把守，后扩再补机检。

### 写作期逐句判读三问（每次写完一段解读/摘要/评价过一遍）

| 问句 | 答"是"就处理 |
|---|---|
| 1. 这句能换成可核实的事实/数字/限定条件吗？ | 能就换。例："速度随水深分档"→ 干巷道 4 m/s、逆水 1 m/s、顺水 2 m/s（值须与模型一致）。 |
| 2. 删掉这句，信息丢了吗？ | 没丢就删（多为段尾宣传句）。 |
| 3. 我写的是图/表里能看到的，还是在复述上段/图注？ | 复述就重写：写图内分布落在哪、哪段先到/后到、趋势归因到机理。 |

### 六类高频模板（写作期自查）+ D 论文实例（改前 → 改后）

| 类 | 识别特征 | 处理 | D 论文实例 |
|---|---|---|---|
| T1 裸图导语 | 无图号的图引用："其效果如图所示 / 见下图 / 效果图如下" | 写具体图号 + 解读锚点（"如图 3 所示 / 由图 3 可见"），可计数短语不可省 | 改前"…可视化，其效果如图所示。" → 改后"…漫延结果见图 X，由图 X 可见，…" |
| T2 段尾拔高宣传句 | 段末自我评价："兼顾了安全性与可执行性""具备较强的跨场景迁移能力""体现了模型的合理性/实用性" | 删；句号收在机制/结构事实。`verify_paper` R3 WARN（名单见下） | 改前"…同时兼顾了安全性与方案的可执行性。" → 删，句号收在"…从当前位置重新规划逃生路径。"；"具备较强的跨场景迁移能力"→ 删，收在"模型主体框架保持不变。" |
| T3 空洞技术断言 | 不可核验的跑量/复杂度："线性复杂度""秒级完成数千节点" | 改成可查证的复杂度记号 + 一次/离线计算 + 实际规模（规模数字一律走结果门面取数） | 改前"…均为线性复杂度…单次求解仅需数秒" → 改后"单源传播用堆优化 Dijkstra，复杂度为 O((V+E)log V)，对附件 1 的端点/边数规模一次求解即为完整结果" |
| T4 解读复述图注/上段 | 整段把公式规则或上一段重讲一遍，不写图里东西 | 看图写实 + 内容要素门三件套（数值/趋势/机理，判据见第二节 5，缺一 FAIL） | 图 11 解读原复述"到达时刻取较早者"叠加规则 → 改后写示意图本身所见：两波前在交汇巷道相遇、界面处的水位分界与推进受阻 |
| T5 解读开句机械同形 | 段首解读短语同一种形态扎堆（旧稿"观察图X可知"×9） | 形态轮换 + 部分锚点移出段首；**强调式**（观察图/结合图/分析表/观察表）同形态 ≤ 解读段 1/3（`verify_paper` R2 INFO 参考） | 9 处"观察图 X 可知" → ≤3 处；其余换"由图 X 可知 / 由图 X 可见 / 由表 X 可知"；≥4 段把锚点从段首移到段中。改后逐图解读锚点总数不变（硬门"解读 ≥ 图表数"只数总数，不卡位置） |
| T6 摘要/结论自夸与题设复述 | 摘要段以复述题设开头、段尾自我表扬 | 走第七节摘要骨架：针对问题 N + 怎么分析 + 怎么做 + 结果数值 | 反面案例见第七节（问题 3、4 合段）；批改后摘要每段以"针对问题 N"开头、立出模型名、给到达时刻等数值（机器摘要结构 PASS） |

### 解读锚点变式（T5 轮换表；均被 `verify_paper.py` 计数，见 interp_count.PATS）

`观察图X可知`　`由图X可知`　`由图X可见`　`由表X可知`　`由表X可得`　`分析表X可知`　`结合图X`

- 每段保留锚点，只换形态与位置；**中性"由图/由表 X 可知"是正常技术语体，不属机械排比**，可放心用。
- 摘要段以"针对问题 N"开头是第七节硬性骨架（机器检查），**不算**机械同形，不得为"求变化"改掉。

### 机检状态与校准阈值（先保守后扩）

`verify_paper.py` 在既有四个硬门之外新增「文风建议（软门，不 FAIL）」：

| 规则 | 抓什么 | 级别 | 阈值常量（verify_paper.py 模块级，扩规则只改常量不动逻辑） |
|---|---|---|---|
| R1 裸图导语 | "如图所示/见下图/如下图所示"等无图号写法（正例"如图 3 所示"不命中） | WARN | `R1_BARE_FIG_PAT` |
| R2 开句同形 | 强调式开句（观察图/分析表/观察表/结合图）机械堆叠 | INFO | `R2_EMPH_MIN = 3` 段、`R2_EMPH_RATIO = 0.4`（占段首锚点解读段比） |
| R3 段尾拔高 | 段末句命中名单：体现…的(合理性/有效性/实用性)、具备/具有较强…的(能力/性)、兼顾了…性、构成完整的…(链条/体系)、充分(验证/说明)了…的(合理性/可行性)、显著…(提高/优于/…) | WARN | `R3_TAIL_PATS` |

- 命中项按上方 T1/T2/T5 改写后复扫到 0 条为佳；不改不影响退出码（风格属主观，交作者定夺）。

### 回归验证（改 skill 后必跑）

`python tools/test_style.py` 必须全 PASS（退出码 0）：

### 允许与边界

- 结论可带专业限定（"在 0.2~0.5 m 阈值范围内…"）；评价节（ch7）可评，但须落到具体机制，禁止形容词空喊。

## 十一、正文与实现一致：说与做对照（2024-E 复盘 / 最高优先级）

> **判断总纲**：论文里每处"方法/口径/数值"描述，必须能指到生成代码实现它的那一行。凡正文"说"的比代码"做"的高、多、玄——公式展示成两期、变量列了一堆、口径写得更细——都是"说与做断裂"。评委一眼看出（公式、变量、计算量对不上），且**全链路自检（check_numbers / verify_paper）全 PASS 也拦不住**：它们只查格式与数字漂移，不查"诚实度"。这类不是 bug，是"诚实度"缺陷。

### 判定三步（每处方法描述过一遍）

1. **能不能指到实现行**：有没有 `mask` 参数？有没有 pre/post 两期？`control` 怎么构造？口径是单日还是累计？
2. **实现是否诚实**：凡近似/启发式/单差/逐日，正文就必须照此表述，绝不换更漂亮的说法。
3. **"说高"立即改文字**（不重构代码）：实现诚实、保守，正文就伺候它；只有实现比正文更聪明时，才考虑改代码。

### E 题模板对照表（正文错 → 应改成）

| 类 | 正文（错） | 实现实际 | 应改成 |
|---|---|---|---|
| 掩码空操作 | "±3 日连续空缺判监控失效" | 逐日"有记录=有效"，无 ±day 窗口 | "记录为 0 的(路口,方向,日)视为覆盖未知并剔除"，并承认对已存在移动该过滤是空操作 |
| DID 名不副实 | 展示两期 ΔY=(Y_T,1−Y_T,0)−(Y_C,1−Y_C,0) | 只算单差 Ȳ_T−Ȳ_C，无 pre/post | 公式改单差 ΔY=Ȳ_T−Ȳ_C，删"双重差分"字样；或真补两期 |
| "匹配变量"未实现 | "以边界流量/时段/覆盖为匹配变量""PSM-DID 思路一致[8]" | `control=[x−7]`，提前一周启发式对照 | 措辞降到"以星期结构与临近性选取匹配对照期""该口径与政策评估中的匹配/差分思路相关" |
| 事件数口径撞名 | "约705起"（实为 5/1 单日）出现在"36天累计18131"之后 | `O_dist=parking_gap(…, pk_days[0])` 是 5/1 当日数 | "事件数"改为"5/1 当日事件数/峰值日事件数"，与累计明确区分 |
| 文献作者/版次错配 | 书名/出版社/年份对，作者列表却是另一版署名 | 同一条目存在两种版次署名 | 逐条联网核对**该版次**作者列表；作者与版次不匹配即改（见第五节 20p、四 铁律） |
| 公式量纲与代码不符 | "v̄_opt=L_tot/(t_free+Δt_obs/r)（声称 km/h）" | solve.py: `v_opt=Ltot/tt_opt_s*3.6`（Ltot 米、tt_opt_s 秒，**×3.6** 得 km/h） | 公式补 `×3.6` 与实现逐字一致；凡"由门面数字支撑"的结果公式，其**单位/量纲折算**（m/s↔km/h、秒↔小时、米↔千米）必须逐一比对代码那行，缺即量纲错 |

### 四条"说与做"自查问

- ① 这句话能换成可核实的事实/数字/限定吗？换不了就删或收窄。
- ② 删掉它，信息丢了吗？（含指代不清的空话：丢了不算损失）
- ③ 我写的是代码真做了的事，还是我想让它做的事？
- ④ 公式里的**单位/量纲折算**逐字照抄代码了吗？（代码 `v_opt=Ltot/tt_opt_s*3.6` 有 ×3.6，公式漏了就是量纲错、重算一遍得 m/s；凡 m/s↔km/h、秒↔小时、米↔千米，逐一比对实现行）
